## 起因

做短剧分镜生成器的时候，最省事的写法是把百炼的 Key 直接写在前端，页面里 fetch 打过去。十分钟能跑通。

但那个 Key 是有额度的，也是我自己的。前端里出现的每一个字符串，最后都会躺在别人的开发者工具里。

## 三条线

- **浏览器不持有 Key**：页面只调同源地址 `127.0.0.1:8787`，Key 只存在 `server.mjs` 的进程内存里
- **服务只监听本机**：`listen(8787, '127.0.0.1')`，同一个 WiFi 下的手机都连不进来
- **`.env.local` 走不出 HTTP**：静态文件服务拒绝一切以点开头的路径，`/..%2f` 这类变形也不会被当成普通文件读

## 顺手加的一个细节

`/api/health` 只回一段掩码，形如 `sk-ws-H.PYDD…Dmad7k`。它足够让我确认「Key 配上了、环境加载了」，但漏不出任何有用的内容。调试的时候这点信息量刚好够。

## 另一处：输出怎么渲染

模型返回的文本最终要显示在页面上。如果直接用 `innerHTML`，一条精心构造的提示注入就能让页面执行脚本。

所有输出统一用 `textContent` 塞进节点。代价是没法用富文本，但分镜本来就只需要纯文本。

## 现在的边界

这套方案只适合本地工具。真要部署到公网，得换成正经的后端代理，加上登录态和限流，否则谁都能刷我的额度。

对一个小工具来说，把攻击面砍到「只有我自己点得开」，就已经够了。
